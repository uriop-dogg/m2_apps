# 検証記録

検証日：2026-09-30

## 数値テスト

`node tests/dsp.test.mjs` で再実行できます。npmインストールは不要です（ES Modulesを扱える現行Node.jsを使用）。

- カンマ区切りの正整数、偶数の奇数化、重複除去、BigInt、不正入力の拒否
- 固定Branchと列挙した番号集合の一致、H/Sの逆数関係、平均律の構成
- 短調主音表示の変換・逆変換、Odd Link=3の位置
- FFTの往復変換
- 3種類のフィルター、複数のキー差で、Both Mix曲線と直接のパワー和を比較（許容誤差2×10⁻¹⁰）
- 再生エンジンの原音再構成、Both Mixが単独出力の振幅平均になること、ステレオ比較がモノラル化後の各フィルター出力になること
- 全曲パワーヒストグラム、無音の拒否

実測最大差：原音再構成 約9.31×10⁻¹⁷、Both Mix 約5.59×10⁻⁹、ステレオ比較 約7.45×10⁻⁹。

## ブラウザでの検証

実際のブラウザエンジン上で、別のローカル専用テストページからアプリ本体を動かしました。テストページ・テスト音声は公開用ファイルには含めていません。

- 合成した8秒のCメジャー和音をPCM WAVとMP3で読み込み、Workerで全曲解析。Both Mixの最大点はいずれもC −0.1 cent付近（WAV約82.669%、MP3約82.671%）
- 最大点がC付近となり、初期状態のBoth Mix自動追従が適用されること
- ドロップイベントからの読み込み
- 短調主音の読み替えによる表示変更と復元、Both Mixの最大点・H側の位置が不変であること
- 独立操作、自動追従オフ、オクターブ境界、最大点移動時のキー差保持
- Odd Link=5、Odd Linkの不正入力と復帰
- 3フィルターの切替、カスタム入力の正規化・エラー・復帰
- 平均律でのラベル変更と短調主音補正の無効化
- 原音を含む5つの試聴モードの選択状態
- 実際のAudioWorkletをOfflineAudioContextで実行し、分割FFTとバッファリングを含めた原音再構成を確認（最大差 約3.07×10⁻¹⁶）
- 任意対応のWebMCPフィルター設定：正常入力と不正入力、画面との同期
- PC幅での画面表示確認

人による実楽曲の試聴評価、全ブラウザ・全デバイスでの連続再生品質、最大長音声の負荷試験は実施していません。音声出力の数値検証と、実際に耳で聴いた音の評価は区別してください。GitHubへのアップロード・公開は実施していません。
