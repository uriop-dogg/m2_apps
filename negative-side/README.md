# ネガレル - Negallel -

音声のネガティブハーモニーを計算できるサイト。
HTML・CSS・JavaScriptだけで動きます。ビルド、APIキー、バックエンド、外部ライブラリ、CDNは不要です。音声はブラウザのメモリ内で処理し、サーバーへ送信しません。

## GitHub Pagesで公開する

1. ZIPを展開します。
2. GitHubに公開用のリポジトリを作成します。
3. `negative-side` **フォルダの中身**をリポジトリ直下にアップロードしてコミットします。`index.html`が直下にある状態にしてください。ZIPそのものをアップロードしてもサイトにはなりません。
4. リポジトリの **Settings → Pages** を開きます。
5. **Build and deployment → Source → Deploy from a branch** を選択します。
6. **main / (root)** を選択して **Save** を押します。
7. 公開処理の完了後、Pagesに表示される `https://ユーザー名.github.io/リポジトリ名/` を開きます。この**サイトのURL**を配布してください。GitHubのコード一覧URLとは異なります。

フォルダごとアップロードした場合は、サイトURLの末尾に `/negative-side/` を付けてアクセスできます。すべての読み込み先は相対パスです。

手順の参照：[GitHub公式・公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)（2026年11月18日確認）。公開は所有者が手動で行います。本成果物から自動公開はしていません。

## 使い方

1. 上部へ音声ファイルを1つドラッグ＆ドロップするか、クリックしてMP3、WAVなどを選びます。対応形式はブラウザのデコーダーに依存します。
2. 元音声を再生して確認します。「元音声を保存」は読み込んだファイルをそのまま保存します。
3. オクターブ基準・A4チューニング・セント値ずれを設定します。初期値はC、440 Hz、0 centです。
4. 反転先をスライダー、整数目盛りボタン、または整数選択で設定します。整数選択には `1`、`3`、`5`、`1/3` などを入力できます。＋／−は `…1/7, 1/5, 1/3, 1, 3, 5, 7…` と移動します。N/Aからの＋／−は1を起点に移動します。
5. 必要に応じて窓長、ホップ長、反復回数を変更し、「変換する」を押します。初期値はAGLA、4096、1024、24回です。
6. 完了後、変換した音声を再生し、「WAVを保存」で保存します。「停止」は計算を中断します。途中音声は保存しません。設定を変更して再実行できます。

ブラウザを閉じる／再読み込みすると音声と結果は消えます。必要な結果は保存してください。

### 反転先と目盛り

- 時計の外周はC〜Bの固定された絶対12平均律位置です。12時がCで、時計回りに半音ずつ進みます。内側の倍音位置だけがオクターブ基準に応じて移動します。
- ×1は基準音、×3は基準から701.955… cent、×5は386.314… centです。
- ×5「平行調（Relative）」、×3「同主調（Parallel）」は、このサイト独自の対応記号です。
- 整数位置を指定すると内部では `c = log2(k) mod 1` を倍精度で直接使用します。スライダーの表示分解能から逆算しません。
- 任意位置では `c = (スライダー位置 − オクターブ基準/12) mod 1` です。
- チューニングとセント偏差は内部周波数だけに反映し、スライダーや倍音位置目盛りを移動させません。
- 表示範囲は `1/7`〜`15` のように指定できます。整数は1〜9999の奇数とその逆数、表示は最大80個です。重なるラベルは段を分けます。
- 吸着は表示中の倍音位置に対し約10.8 cent以内で働きます。自由に位置を選ぶときは吸着をオフにできます。キーボード操作では微調整を優先します。
- 円環なのでBから先はCに戻ります。

## 音声処理

`dsp.js` と `worker.js` がNH変換を担当します。

基準周波数は `f0 = A4 × 2^((音名番号−9)/12 + cents/1200)`。音名番号はC=0、A=9、B=11です。

正の周波数fに対し、

```
x = log2(f/f0)
n = floor(x)
r = x - n
r' = (c - r) mod 1
f' = f0 × 2^(n + r')
Aout(f,t) = Ain(f',t)
```

元STFTの**振幅**をFFTビン間で線形補間します。パワーの再配置ではありません。`(2c-r)`は使用しません。各オクターブは下端を含み上端を含まない区間です。DCはDCの振幅を保持し、参照周波数がナイキストを超えた出力ビンは0にします。DC・ナイキストの虚部は常に0です。

周期的Hann窓、前後N/2以上のゼロパディング、窓二乗和による逆STFT補正を使用します。末尾はホップ単位の端数を追加パディングし、出力は元のサンプル数に切り戻します。

元位相は引き継がず、固定シード `0x6d2b79f5` の乱数位相からGriffin–Lim法で反復します。初期再合成の後に指定回数の位相更新を行います。チャンネルごとに独立して処理し、同じシードを使用します。左右を混ぜません。一般の倍音列は崩れます。再音符化、調性推定、メロディ抽出は行いません。

全チャンネルで最大ピークを求め、−1 dBFSを超えた場合だけ全チャンネルを同じ係数で減衰します。増幅・チャンネルごとの正規化はしません。16-bit PCM WAV（ディザなし）を出力します。量子化によるごく小さな丸め誤差があります。

ブラウザの音声デコード時に端末のAudioContextサンプルレートへ変換される場合があります。出力はデコード後のサンプルレート・チャンネル数・長さを維持します。入力ファイルの元サンプルレートそのものの維持は保証しません。

## 背景色の独立した解析

`spectrum-worker.js` が担当し、NH変換コードを読み込みません。

各チャンネルの**音声全体を一度にFFT**します。末尾を次の2の累乗までゼロ埋めします。短時間スペクトルの平均ではありません。DCを除く全正周波数のパワーを、`log2(f/440) mod 1` の円環上360区間へ線形配分し、チャンネル間で平均して正規化します。逆相のL/Rも打ち消し合いません。

この分布から各光の色相を確率的に選びます。タイプ1はA＝赤、タイプ2はC＝赤（90度の移動）。最大ピークだけを採用する方式ではありません。無音時は初期の背景を維持します。動きの軽減設定にも対応します。

長い音源向けに、FFTをin-placeで計算し、巨大なビット反転表・三角関数表は持ちません。作業領域は2本のFloat32配列、合計約8×FFT点数バイトです。チャンネルごとに領域を再利用します。上限は2^25点（48 kHzで約699秒、44.1 kHzで約761秒）で、それ以上は背景解析だけを省略し画面に表示します。NH処理を開始した時点で背景解析がまだ続いている場合は、変換を優先して背景解析を停止します。

## 負荷と制約

- 初めは短い音声で試してください。PCのほうが長い音源を扱いやすく、スマホではメモリ不足でタブが閉じる可能性があります。
- 窓長は4096／8192／16384／32768。ホップ長はN/16〜N/2の整数、反復回数は1〜256です。窓長変更時はホップ長をN/4に戻します。
- A4は100〜1000 Hz、偏差は±1200 centの範囲です。
- NH作業メモリ概算が900 MBを超える条件は開始前に止めます。表示値は音声デコード・ブラウザ・転送コピーなどを含む総使用量ではありません。実際にはより多くのメモリが必要です。
- Workersで重い処理を画面から分離しています。ただし巨大ファイルの読み込み・デコード・コピーには時間がかかります。
- スマホでは画面消灯や別アプリへの移動で処理が休止することがあります。変換中はページを開いたままにしてください。
- ブラウザ間の微小な浮動小数点差、デコード差、Python版とのFFT・初期乱数・パディングの違いにより、以前の試作と完全には一致しません。以前の楽曲試作との聴感比較は今回実施していません。
- ファイルをダブルクリックした`file://`ではWorkerが制限されるため、GitHub PagesのHTTPS URL、またはローカルHTTPサーバーで開いてください。

## 位相推定方式の切替（2026年11月19日）

「位相推定方式」でGriffin–Lim（従来）、Fast Griffin–Lim（FGLA）、Accelerated Griffin–Lim（AGLA、初期選択）を選べます。反復回数は各方式とも同じ欄で指定します。まず同じ設定・回数で両方を保存して聴き比べ、次にFGLAの回数を減らして比較できます。再変換時は画面の前の結果を置き換えるため、比較用のWAVは先に保存してください。保存名は元ファイルの拡張子を除いた名前に `_negative.wav` を付けます（例：`Coffee_motif.wav` → `Coffee_motif_negative.wav`）。結果欄には実行時の方式と反復回数を表示します。

FGLAは加速係数m=0.99を固定使用します。再解析STFTをZとすると、初回はarg(Z)、以後はarg(Z_current − m/(1+m) × Z_previous)で位相を更新し、指定振幅へ戻します。保存する履歴は加速前の複素STFTです。参照：[librosa公式実装](https://librosa.org/doc/main/_modules/librosa/core/spectrum.html)。既存のNH振幅写像、固定シード、窓、パディング、チャンネル処理、共通ゲインは維持しています。

前回STFTの実部・虚部をFloat64で保持するため、FGLAは追加で16×フレーム数×ビン数バイトを使います。画面の見積もりと900 MBの開始制限に反映します。同じ反復回数の処理が必ず速くなるわけではなく、同等の再現性に必要な反復数を減らせるかを比較するための選択肢です。音源ごとの聴感品質改善は保証しません。

追加数値試験：node tests/fgla-test.cjs

## 時計型メーターへの更新（2026年11月19日）

名称を「ネガレル - Negallel -」へ変更しました。中央の針の先端をドラッグするか、円周をクリック／タップして反転先を指定します。倍音位置への吸着・直接入力も使用できます。オクターブ基準の変更で倍音位置と針が回転し、チューニングとセント偏差では回転しません。

メーターにキーボードフォーカスを合わせると、矢印キーで1 cent、Shift併用で10 cent、PageUp／PageDownで100 centずつ移動します。Homeで固定音名Cの位置に戻ります。円環の端を越えると反対側へ続きます。

近接した倍音位置ラベルは内側の別の円周へずらします。それでも収まらないラベルは右側の「倍音位置の一覧」から選べます。一覧には表示範囲内の全倍音位置を収録します。小さい画面では時計を上、その下に基準と倍音位置を配置し、縦スクロールで操作します。既存の保存フォルダ名negative-sideは継続しています。

### 水晶玉と後光の色
時計中心の水晶玉と外周の後光は、全体FFTで得た音名分布を確率として色を選びます。約6.5秒ごとに抽選し5秒かけて同じ色へ移ります。未読込・無音時は全色から抽選します。光の色でA＝赤／C＝赤を切替可能。非表示タブでは抽選を休止し、戻ると再開します。視覚効果は glow.js に分離しています。従来のページ背景の漂う光は、この水晶玉と後光に置き換えました。

### 聴き比べプレーヤー
共通の再生バーで再生・一時停止・シーク・音量調整ができます。変換完了後は上部の小さな「元音声」「変換後」ボタンで現在の再生位置を引き継ぎます。選択中の音声はボタンの色で表示します。一時停止中は停止状態を維持します。ブラウザの音声再生機構を使用するため、切替時の無音時間が完全にゼロになることは保証しません。

### 日本語／English
画面上部の言語メニューで日本語と英語を切り替えられます。操作項目、進捗、アプリのエラー、使い方ガイドに対応しています。言語の切替では読み込んだ音声・変換結果・設定を保持します。選択した言語は端末のローカルストレージに保存します（保存が制限された環境でも切替可能）。ブラウザ自体のエラーメッセージはブラウザの言語に従う場合があります。翻訳データは同梱され、外部の翻訳サービスは使用しません。


## 2026-11-20：位相投影の高速化

GLA／FGLAの位相更新では、角度への変換と三角関数による復元を、複素数の方向の正規化に置き換えました。各フレームの位相更新直後に再合成し、前回波形と次回波形のバッファを分離します。零ベクトルは位相0相当、DCとナイキストは実数に制約します。初期乱数・振幅写像・窓・反復回数・左右共通ゲインは維持しています。旧版とは丸め処理が異なるため、波形の完全一致は保証しません。

固定の高速化率は保証しません。検証用音源のNode測定では窓長8192で約14％短縮しましたが、32768では明確な差はありませんでした。不要な位相配列を廃止し、追加波形バッファを含むメモリ見積もりも更新しています。音源は公開用ファイルに含みません。


## 2026-11-20：AGLA追加

初期設定はAGLA・24回です。GLA／FGLAも選べ、方式を切り替えても入力した反復回数は維持します。AGLA係数は試聴済みの alpha=0.95、beta=1、gamma=1.3 に固定。

NenovほかのAGLA更新式（Algorithm 3）を、STFTの線形性を利用してパディング済み波形領域で実装しています。初期状態は同じ固定乱数位相を合成した波形でc0=t0=d0。最終出力は、試作と同様に最後の振幅投影を逆STFTした波形です。論文の最終加速状態を直接出力する処理とは異なります。参照：https://arxiv.org/abs/2306.12504

GLA／FGLAの更新式と出力はこの追加では変更していません。NHのc-r写像、窓、半窓パディング、窓二乗和補正、固定シード、チャンネル数、左右共通ゲイン、PCM16保存も維持しています。AGLAの状態用にFloat64波形を2本追加し、前回STFTの履歴配列は使いません。メモリ見積もりと900MB制限に反映済みです。

検証用の約37秒の音源では、4096／8192／16384のAGLA24回出力が試聴済みの試作WAVと完全一致しました。すべての音源で同じ速度向上や聴感品質を保証するものではありません。サンプル音源は配布物に含みません。
