# 検証記録

実施日：2026年11月18日。Windows上のNode.jsおよびChatGPT内蔵のChromium系ブラウザで実施。

## 音声処理の数値試験

| 試験 | 結果 |
|---|---|
| FFT→逆FFT | 4096点、最大誤差1e-12未満 |
| 正式写像 | ×1、×3、×5、×1/3、×1/5、各1999周波数で同一オクターブ内・往復誤差1e-10未満 |
| 誤定義の回帰防止 | f0=440、入力440、×3で660 Hzとなることを確認 |
| 固定シード | 同一入力・設定の64回反復を2回実施し、Float32出力配列が完全一致 |
| 音量比 | 右音声を左の0.25倍にした試験で、処理後も0.25倍（誤差1e-5未満） |
| ピーク制御 | 2.0ピークの入力に−1 dBFS / 2の共通ゲインを適用 |
| WAV | PCM形式、モノ／ステレオのチャンネル数、サンプル数、ヘッダー長を検証 |
| 窓長4種 | 4096／8192／16384／32768で非無音入力を64回反復。長さ維持・非無音・全サンプル有限 |
| 無音・短音声 | 全窓長で21サンプルの無音が有限なゼロ出力となることを確認 |
| エンジン全体の周波数 | 640 Hz正弦波、f0=256、×3、窓8192、64回反復。理論614.4 Hzに対し出力の最大FFTビン614 Hz |
| 背景FFT | 全体FFTの集計を独立した直接DFTの計算と比較、正規化分布の最大差1e-6未満 |
| 背景のステレオ | L/Rが逆相でもスペクトル強度が消えないことを確認 |

主要な数値試験は `node tests/self-test.cjs` で再実行できます。単音スペクトル試験は `node tests/tone-test.cjs`、背景の独立DFT比較は `node tests/spectrum-test.cjs` です。Node.jsは試験にのみ使用し、公開サイトの実行には不要です。

## ブラウザでの操作試験

- 合成した1秒・44.1 kHz・2チャンネルの16-bit WAVをファイル選択で読み込み。
- デコード後は48 kHz・2チャンネル・1秒となることを画面で確認。
- C基準・×3・窓4096・ホップ1024・64回反復で完了（この端末では約2.8秒）。
- 最終版でB基準・×3・窓4096・ホップ1024・64回反復を実行、約3.0秒で完了。
- 出力プレーヤーの再生を操作し、再生中状態への遷移を確認。
- WAVダウンロードを実際に実行。保存されたファイルのヘッダーとPCMを別途確認。C基準試験の出力は2チャンネル・48 kHz・48000フレーム、ピーク約0.318573で非無音。
- 256回反復の実行を途中で停止。停止メッセージと再実行可能状態を確認。
- B基準・×3でスライダーが固定C基準座標の約50.1629%になることを確認。
- A4=442、偏差=12.5 centでf0=499.7234 Hzに変わり、×3の位置と選択値は維持。
- 逆数 `1/3` の直接入力が498.045 centへ即時反映。＋操作で1、3へ順に移動。
- スライダーのキーボード微調整でN/Aとなることを確認。
- 1/7〜15の目盛りを表示し、近いラベルが複数段に分かれることを確認。
- 390×844の表示領域で、入力欄の縦配置、2段の音名目盛り、結果プレーヤーと保存ボタンを目視確認。
- JavaScript構文検査を実行。ブラウザ検証中のエラー／警告ログなし。
- 読み込み先がすべて相対パスであることをソース確認。外部通信を行うコード、外部ライブラリ、APIキーはなし。

## 未実施・制約

- GitHub Pagesへの実際の公開は未実施（所有者が手動公開するため）。
- iPhone／Android実機、Safari／Firefoxでの実行、各圧縮音声形式、長時間楽曲の実測は未実施。
- スマホ幅の検証は表示領域変更によるもので、スマホ実機での処理性能を保証しない。
- 元のPython試作・楽曲添付ファイルとの比較や、聴感品質の一致確認は未実施。
- 処理速度は試験条件と端末に依存する。長い音源はメモリ・時間ともに増加する。
- 背景FFTは2^25点を超える場合に省略する。NH作業メモリ概算が900 MBを超える場合は開始を止める。

付属の試験音声は440 Hzと660 Hzを合成したテスト信号です。楽曲のサンプルではありません。
