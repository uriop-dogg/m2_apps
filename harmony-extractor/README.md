# Harmony Extractor — Web Edition

音声を読み込み、ハーモニクス／サブハーモニクスの響きと全曲エネルギー曲線を比較する、PC向けの静的Webアプリです。

## GitHub Pagesで公開する

1. ZIPを展開します。
2. GitHubに公開用リポジトリを作ります。
3. **このフォルダーの中身**をリポジトリの最上位へアップロードします。リポジトリを開いてすぐ `index.html` が見える配置にしてください。ZIPそのものをアップロードする方式ではありません。
4. リポジトリの **Settings → Pages** を開きます。
5. **Source: Deploy from a branch**、アップロードしたブランチ（通常 `main`）、**/(root)** を選び、Saveします。
6. 公開処理が完了したら、Pages画面に表示されるHTTPSのURLを開きます。そのURLを共有してください。

ビルド、npmインストール、APIキー、音声処理サーバーは不要です。相対パスを使っているので、リポジトリ名を含むPages URLでも動作します。`.nojekyll` も同梱しています。

公式手順：[GitHub Pagesの公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 手元で開く

`index.html` のダブルクリック（file://）ではモジュールや音声処理が動きません。HTTPS、またはlocalhostのHTTPサーバーが必要です。

Node.jsがある場合は、このフォルダーで次を実行します。

```sh
node preview.cjs
```

表示された `http://127.0.0.1:4173` をブラウザで開いてください。終了はターミナルの Ctrl+C。すでに4173番ポートが使用中なら `node preview.cjs 4174` のように変更できます。

公開後はNode.jsも不要です。参考：[AudioWorkletの動作条件](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletNode)

## 操作

1. MP3・WAVなどをドロップするか「ファイルを選択」で開きます。
2. 初期状態ではH・S倍音枝、Odd Link=3、最大点対象Both Mix、自動追従オンです。読み込みだけでは再生しません。
3. 解析が終わると、Both Mixの最大点へ両側の音名基準が移動します。
4. 再生し、ハーモニクス・サブハーモニクス・Both Mix・原音を切り替えて比較します。ステレオでは入力をチャンネル平均して、左が第1系列、右が第2系列になります。
5. グラフのチェックで表示曲線を選べます。点線は各曲線の最大点、破線は現在の音名基準です。曲線の表示と再生音の選択は独立しています。
6. 「最大点の対象」を選び、グラフのクリック、最大点ボタン、局所ピークボタンで移動できます。局所ピークの順番はエネルギーの大きい順です。

### 最大点への追従

音声やフィルター、キー差を変えて新しい曲線が計算されたときに、選択対象の最大点へ移動します。チェックをオンにしたとき、対象を切り替えたときも移動します。手動で音名基準を動かすだけで直ちに元へ戻す機能ではありません。ただし独立操作でキー差が変わるとBoth Mixが再計算されるため、追従オンならその計算後に移動します。自由に探索したいときはオフにしてください。

### 短調主音への読み替え

「音楽理論的短調主音に合わせる」をオンにすると、サブハーモニクス側の表示座標を `−1200 log₂(3)` centだけずらします。再生音、フィルターの実際の位置、Odd Linkの関係、エネルギー値は変えません。短調側のスライダー・cent入力・曲線・最大点が同じ読み方に変わり、操作時は逆変換します。Both Mixの横軸は常に第1系列基準です。平均律では補正を適用しません。

## フィルター

|種類|構成|
|---|---|
|H・S 倍音枝|Branch `(1,5), (3,9), (5,13)`。編集不可|
|長・短 平均律|12平均律のMajor `0,2,4,5,7,9,11` と自然短音階 `0,2,3,5,7,8,10`|
|カスタム倍音|共通の正整数一覧からHとSを生成。初期 `1,3,5`|

カスタム入力では2の因子を除き、重複を削除します。0、負数、小数、空の項はエラーです。整数の正規化はBigIntを使い、大きい番号でも整数として処理します。実際の音声計算は倍精度浮動小数点です。過大な入力による停止を避けるため、入力全体16,384文字、1,024項、各番号256桁までとしています。

## 音声と計算

- 音声ファイルと解析結果は端末内に留まります。アプリからの音声アップロード、アクセス解析、外部ライブラリ・外部フォントの読込はありません。ページ本体の取得は通常のWeb通信です。
- 対応形式はブラウザのデコーダーに依存します。PCM WAVとMP3の読み込み・解析を確認済みです。その他の形式もブラウザでデコードできれば利用可能です。読めない場合は画面にエラーを表示します。
- ブラウザの `decodeAudioData` によって再生コンテキストのサンプルレートへ変換されます。その同じPCMを解析と再生に使います。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)
- A4=440 Hz、ガウス幅1/64（比の差）、最寄り中心によるゲイン、オクターブ同値は従来版に準拠しています。
- 再生FFT長は16384固定、平方根Hann窓、50%オーバーラップ。キーはフレームごとに差の40%を追従し、切替は2フレームのクロスフェードです。
- 音切れを抑えるため、音声処理のFFTを複数コールバックに分けています。処理上の遅延は24,576サンプル（48 kHzで約0.512秒）にデバイス側の遅延が加わります。元のC#版と同じ遅延ではありません。
- Both Mixは振幅 `(A+B)/2`。原音も同じ窓処理と遅延経路を通るため、切替時の時間差を避けられます。音量の初期値は75%。出力制限は従来同様±1.5です。
- モノラルは両側へ、通常の多チャンネル入力は先頭2チャンネル、ステレオ比較は全チャンネル平均を使います。解析は全チャンネルのパワーを合計します。
- 全曲の前後8秒をゼロ埋めし、必要長以上の2の累乗のFFTから、65,536区間の音名パワーヒストグラムを作ります。DC・Nyquistは除外します。
- 単独曲線とBoth Mix曲線はパワー応答との循環相関です。Both Mixのキー差は実際の0.1 cent単位の位置差を使います。最大・局所ピークは放物線補間します。
- Web Workerで解析し、フィルター変更時はヒストグラムを再利用します。古い条件の結果は画面に適用しません。
- エネルギー曲線は通過スペクトルパワー比で、再生時の窓処理・平滑化・出力制限を測定した値や波形一致率ではありません。

### 全曲解析の長さ・メモリ上限

この版ではFFT長の上限を2²⁴にしています。前後のゼロ埋めを含め、48 kHzで約5分33秒、44.1 kHzで約6分4秒までが目安です。上限付近では数百MBのメモリを使い、PCによってはこれより短い音声でも負荷が高くなります。上限超過時には解析を行わず、理由を表示します。読み込めた音声の試聴・手動操作は引き続き利用できます。

## ファイル構成

- `index.html` — 画面・日本語の案内文
- `style.css` — レイアウトと配色
- `app.js` — 状態、操作、グラフ、音声読み込み
- `dsp.js` — 系列・FFT・フィルター・曲線・再生エンジン
- `analysis-worker.js` — 全曲解析
- `audio-worklet.js` — 再生スレッドへの接続と分割実行
- `preview.cjs` — 開発用のローカルサーバー（公開ページからは実行しません）
- `tests/dsp.test.mjs` — 数値テスト。`node tests/dsp.test.mjs` で実行
- `VALIDATION.md` — 検証した項目と範囲
